# iosim commands

Global flags go before the command: `--device <udid|name>` (default `IOSIM_DEVICE`, else the only booted iOS simulator) and `--agent-device "<command>"` (default `IOSIM_AGENT_DEVICE`).

| Command | What it does |
| --- | --- |
| `doctor` | Checks Python, Xcode, the iOS runtime, devices, `ios_webkit_debug_proxy`, agent-device, Node and ffmpeg. Exits 1 on a required miss and gives the fix for each. With agent-device, it also checks that the device is not held by another agent-device session (with a given command, by opening Safari through it, which also checks the command drives this simulator). On a box with no Simulator, it points at the remote path and tests `IOSIM_REMOTE` when that is set. |
| `device list` | iOS simulators with UDID, state and runtime. |
| `device ensure [--type "iPhone 15"] [--name N] [--no-boot]` | With `--name`, finds or creates that simulator. Without it, reuses any simulator of that type (booted ones first, so possibly one another agent is using) or creates `<type> (iosim)`. Creation uses the newest runtime that supports the type. Then boots it. |
| `device boot`, `device shutdown`, `device status` | Shutting down also stops the device's proxy. `status` shows Text Size, appearance, proxy, recording and driver. |
| `text-size [SIZE]`, `appearance [light\|dark]` | Read, or set then read. |
| `open URL [--new-tab] [--no-wait] [--timeout 45]` | Navigates the tab iosim drives (the one the last `open` recorded) or, with `--new-tab`, when Safari has no page, or when iosim has not recorded a tab it can still find, opens the URL through the device. Waits for `readyState == "complete"` on a document that loaded after the call, in that tab only. Fails at once when an http(s) URL ends on Safari's error page (a `data:` URL, for example a server that is down), and when the tab goes away. A redirect to another http(s) page passes with `redirected: true`. `about:blank` blanks the driven tab and needs one. Reports `finalUrl`, whether it redirected, the tab's inspector `page`, and `visible` (whether it is the tab on screen). Records that tab: later commands address it by identity, never by URL. |
| `pages` | The Safari pages the inspector sees; `driven` marks the one iosim drives. |
| `eval EXPR`, `eval --body CODE`, `eval --file F` | Runs JavaScript in the page and prints `value` as JSON. Promises are awaited. A page exception exits 1 with its message. An expression cannot contain statements: use `--body` with `return`. A file may hold either: iosim reads it as an expression first, and as a function body only if that does not parse. If the connection drops after the code was sent, iosim says so rather than running it again. |
| `console [--all]` | Errors (or every message) since the page loaded: console calls, uncaught exceptions and unhandled rejections. |
| `wait --selector S \| --text T \| --js E \| --ms N` | Polls every 250 ms up to `--timeout` (15 s). An expression that does not parse fails at once. One that throws while running (`window.app.ready` before `app` exists) keeps being polled; at the timeout the error names the last exception and suggests `?.`. |
| `tap --selector S [--first] \| --label L [--contains] \| --at X Y` `[--expect S]` | A real tap through agent-device. `--selector` must match one element (`--first` takes the first of several); iosim refuses when the driven page is not the tab on screen, scrolls the element into view if needed, hit-tests its centre with `elementFromPoint` (and fails naming the element that covers it), places the page on screen (or refuses, see below), taps the centre, and then checks in the page that the element got the touch. `--label` is the exact accessibility label as `agent-device snapshot` shows it; `--contains` matches a case-insensitive part of it and must find one element. With `--label` or `--at`, `--expect S` makes the same check against `S`; without it the answer only reports `pageHit`, the element the page saw the touch on (null when none did: Safari's own UI, an iframe or another tab). |
| `type TEXT [--selector S] [--first] [--enter] [--keep-keyboard]` | Types with the keyboard. With a selector, taps the field first (checked like `tap --selector`) and fails, typing nothing, unless it then has focus (`document.activeElement`). Dismisses the keyboard afterwards. |
| `scroll up\|down\|top\|bottom [--amount F]`, `scroll --to S` | A swipe through agent-device, or a programmatic `scrollIntoView`. |
| `shot PATH` | A screenshot at device resolution (1179 x 2556 on an iPhone 15), with the `check-shot` result. |
| `record start PATH`, `record stop` | A screen recording. The state lives in `IOSIM_HOME`, so start and stop can be separate calls. Expect 0.15 to 0.6 MB a second at full resolution (a still page is small, scrolling is large); agent-device keeps the captured resolution. To shrink one afterwards on macOS: `avconvert --preset Preset960x540 --source video.mp4 --output small.mp4`. |
| `check-shot PATH [--expect WxH]` | PNG size, and whether it is blank (luminance spread from a `sips` thumbnail, macOS only). |
| `contact-sheet VIDEO --out PNG [--frames 12]` | Tiles frames into one PNG: ffmpeg when installed (evenly spaced frames, 4 columns), else `agent-device record contact-sheet` (macOS, cells where the screen changed). |
| `audit [--script F] [--min-target 44] [--min-input-font 16] [--warn-only]` | The page audit (see SKILL.md), sizes in CSS px. Exits 1 on any `fail` finding. `--script` takes a project's own file in the shapes plan.md lists; any other result shape, or a severity other than fail or warn, is an error. |
| `run PLAN --out DIR [--var K=V] [--check]` | Runs a plan (see plan.md). `PLAN` may be `-` for stdin. Before anything else, replaces `DIR/report.json` with a `passed: false` placeholder. |
| `proxy start\|stop\|restart\|status` | This device's inspector proxy. Other commands start it as needed. |
| `cleanup [--keep-session]` | Stops the proxy and any recording iosim started on the device, and closes the agent-device session of the command in use (the given command's own, or `iosim-<udid>`), never another. Inside T3, call `device_close` afterwards. |
| `remote ARGS…` | Runs `iosim ARGS…` on the Mac named by `IOSIM_REMOTE` (see remote.md). |

## How it works

- **JavaScript, console, audits**: `ios_webkit_debug_proxy -s unix:<socket>` bridges the simulator's Web Inspector socket to WebSockets. iosim finds the socket of one simulator with `xcrun simctl getenv <udid> RWI_LISTEN_SOCKET`. It runs one proxy per simulator, from port `IOSIM_PROXY_PORT` (default 9320; pages on port + 1), and moves 20 ports up when the block is taken. The proxy restarts by itself when the simulator reboots and its socket moves. The WebKit page socket speaks to targets: each command is wrapped in `Target.sendMessageToTarget`, and answers come back in `Target.dispatchMessageFromTarget`. A bare `Runtime.evaluate` answers "'Runtime' domain was not found". WebKit ignores `awaitPromise` on `Runtime.evaluate`, so iosim awaits the returned promise with `Runtime.awaitPromise`. A cross-site navigation swaps the target (`Target.didCommitProvisionalTarget`), and iosim follows it. `Console.enable` replays the messages the current document has logged, so `console` sees errors from page load as well.
- **Device actions**: these go through agent-device when one is given or on PATH: opening a URL in a new tab, tap, type, swipe, screenshot (`--pixel-density 3`), recording (`--scope device`), Text Size and appearance. Otherwise iosim uses `simctl openurl`, `simctl io screenshot`, `simctl io recordVideo` (stopped with SIGINT) and `simctl ui`. agent-device needs a Safari session, so iosim opens Safari through it once per command.
- **Selector taps**: the element's rect comes from the page in CSS px, which equal screen points at zoom 1 (iosim subtracts the `visualViewport` offset and multiplies by its scale otherwise). Where the page sits on screen comes from anchors: the target and up to 29 other visible named elements, matched by label and size against the nodes inside the WebView of an agent-device accessibility snapshot. Each match gives a screen offset; offsets within a point form one cluster, and the cluster with the most anchors is used (y = 59 under the status bar on an iPhone 15). iosim refuses when two clusters have as many anchors, when the best has a single anchor whose name is not unique both on the page and in the snapshot (an iframe can repeat it), and when another cluster exists and the best rests only on repeated names (rows of identical buttons). When the snapshot also has the web area node labelled with the page's title, its position must agree within 2 points. With no anchor match, that node alone places the page; with neither, iosim refuses. A centre outside the page's visible area (under Safari's toolbar) is refused too. Checked on an iPhone 15 (iOS 27.2) with the compact toolbar, the two-row toolbar at `accessibility-medium`, and the collapsed toolbar after a long scroll.
- **Tap check**: before every selector tap (and `--label` or `--at` tap with `--expect`), iosim adds a one-shot capturing listener for `touchstart`, `pointerdown`, `mousedown` and `click` to the driven page. It ignores events the page's own script dispatched (`isTrusted` false), records the first real event's target and whether the expected element is in its path, and logs the record so it reaches iosim even if the tap starts a navigation. The tap fails when the record names another element, or when there is none (the touch hit Safari's UI, an iframe or another tab). This check, not the placement, is what a green tap rests on.
- **New tab**: `open --new-tab` (and the first `open`) accepts a tab that did not exist before the call, or a tab that was already open only when it has loaded a new document and is the tab on screen (Safari switches to a tab that already shows the URL). A background tab that reloaded by itself is passed over.
- **Driven page**: `open` records the tab it loaded by its inspector page path and Safari's process id, which stay the same while the tab lives and across navigations to other sites, together with the proxy process that numbered it. Every command that runs JavaScript addresses that tab. It fails with `is gone` when the tab has closed or Safari restarted, and with `the inspector proxy restarted since open` when the proxy was replaced (`proxy restart`, `cleanup`, a crash), because a new proxy numbers the tabs afresh: run `open` again. With nothing recorded, iosim uses Safari's only page, or refuses when there are several.
- **Device binding**: when the given agent-device command names its simulator (`--udid`) or a live session (`--session`, looked up with `session list`), iosim checks it before any device action. T3's command names neither, so iosim learns its simulator from the answer to its first `open`: Safari opens on the command's simulator before iosim refuses a mismatch. A `DEVICE_IN_USE` answer becomes an error that names the session holding the device and how to free it.
- **State**: proxy, recording and agent-device session state live in `IOSIM_HOME` (default `~/.cache/iosim`), so separate calls share them. A per-simulator lock keeps two commands from starting two proxies, and iosim checks a saved pid is still `ios_webkit_debug_proxy` (or `simctl`) before signalling it.

## Gotchas

- The first agent-device action on a machine may need to build its XCTest runner, which can take a while; usually it is already built and a call takes about a second. The first accessibility snapshot of a page can take several seconds.
- Opening through the device (`--new-tab`) usually adds a tab, but for a URL a tab already shows, Safari may reload that tab instead. `open` without `--new-tab` reuses the current tab.
- Safari can hold several tabs; iosim drives the one the last `open` recorded, whatever its URL. A link with `target=_blank` puts another tab on screen: the driven tab is then hidden, taps refuse and plan screenshots fail until you `open` again. Keep to one tab when you can.
- `localhost` inside the Simulator is the Mac.
- `simctl ui content_size` and `agent-device settings text-size` take the same names.
